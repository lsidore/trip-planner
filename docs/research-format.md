# Research files format

Every research agent writes JSON files in its trip's `research/` folder (`trips/<slug>/research/`). The scripts read
them to build the page (`python3 scripts/build.py`). This page lists every file the scripts read: who writes it, its
fields and one short example. The sample trip has a complete, valid set: `examples/sample-trip/research/` (read it when
in doubt; its stages are `lisbon`, `comporta` and `porto`).

File names and JSON keys stay in French, as the scripts expect them. Each table explains them in English.

## Common rules

| Rule | Detail |
|---|---|
| Encoding | UTF-8 JSON, written in one go (never a half-written file). |
| Shared files | Several agents may write `acces-logements.json`, `couts-unites.json`, `logements-exclus.json`, `sources-photos.json`, `sorties-<stage>.json`, `lieux-agenda.json`, `trajets.json` and `formalites.json` at the same time. Never rewrite them whole: put your entries in a fragment of the same shape and merge it with `python3 scripts/merge_json.py <target> <fragment>` (or `-` to read it from stdin). The merge is locked and keeps everyone's entries. |
| Money | `_home` = an amount in the travelers' home currency (`currency.home` of trip.json), a plain number without symbol. Prices are **for the whole group** unless the field says otherwise. `prix_couple_home` is an old name: it also means "for the whole group". |
| Real cost | A price includes fees, taxes, service and cleaning. What the price leaves out goes in its own field or line (never "all-inclusive"). |
| Dates and times | Dates `YYYY-MM-DD`; times `HH:MM`, 24-hour, local time of the stage. |
| Links | `https://` only. An `http://` address anywhere in a text is reported as an error. |
| Sources | Every price or dated fact carries its site, its URL and its check date (`verifie`, or `"https://... (checked 2026-11-07)"` in `sources`). |
| Language | Free-text fields (`pourquoi`, `resume`, `conseil`...) are written in the trip's `language`. |
| Ids | A lodging id is `<stage>-<nn>` (`lisbon-01`, two digits, unique in the trip). A place or outing id is `<stage>-<short-name>` (`lisbon-alfama-walk`). The stage key prefix is mandatory: the checks and the page find the stage through it. |
| `_example` | `"_example": true` marks the sample's invented data. Never put it in a real trip. |

**Validation.** `python3 scripts/check_research.py --trip trips/<slug>` checks `acces-*.json`, `sorties-*.json` and
`formalites*.json` (fields, lists of allowed values, https links, dates, stage prefixes, outings that match their
places). It prints one problem per line and exits 1 when there are problems. `python3 scripts/build.py --trip
trips/<slug>` then reports anything not researched yet and stops on an outing without its place.

## Who writes what

| File | Written by |
|---|---|
| `logements-<stage>.json`, `logements-<stage>-<pass>.json`, `logements-exclus.json` | stay-finder |
| `resorts-fiches-<stage>.json`, `couts-unites.json`, `acces-logements.json` | stay-finder |
| `sources-photos.json` | stay-finder (only when the automatic photo search fails) |
| `vols-brut/`, `vols-comparateurs.json` | flight-hunter (through `scripts/flights.py`) |
| `trajets.json`, `formalites.json` | logistics-planner |
| `lieux-<stage>-activites.json`, outings in `sorties-<stage>.json` | activity-scout |
| `lieux-<stage>-restos.json`, outings in `sorties-<stage>.json` | food-scout |
| `lieux-agenda.json`, outings in `sorties-<stage>.json` | events-hunter |
| `taux.json` | budget-keeper |
| `photo-guides.json` | any scout (optional) |
| `vols-options.json`, `lieux-photos-extra.json`, `previews/`, `medias-cache/`, `poi-cache/` | generated by the scripts: never edit |

Free notes (`research/<date>-<topic>.md`, for example `2026-11-07-stays-lisbon.md`) are welcome next to the JSON
files: sources, what was compared, what could not be checked.

## Lodgings

### `logements-<stage>.json` (stay-finder)

A list of lodgings (a `{"options": [...]}` object also works). Extra passes for the same stage can go in
`logements-<stage>-<pass>.json` (for example `-airbnb`, `-pepites` for hidden gems, or a zone name); duplicates (same
Airbnb listing or same name) are dropped, the first one found wins.

| Field | Type | Required | Meaning |
|---|---|---|---|
| `id` | string | yes | `<stage>-<nn>`; also the folder name of its photos |
| `nom` | string | yes | name |
| `prix_total_home` | number | yes | total price of the stay for the group (all nights, fees and taxes) |
| `url` | https string | yes | the listing |
| `etape` | string | recommended | stage key |
| `plateforme` | string | recommended | site of the price (`Booking.com`, `Airbnb`, hotel website...) |
| `prix_nuit_home` | number | recommended | price per night |
| `nuits` | integer | recommended | nights (default: the stage's nights) |
| `checkin`, `checkout` | date | recommended | dates priced |
| `zone`, `sous_zone` | string | recommended | area, finer area |
| `lat`, `lng` | number | recommended | position (map link) |
| `type`, `style` | string | recommended | kind of place, look and feel |
| `vue` | string | recommended | the view, as seen on the photos |
| `piscine` | boolean | optional | pool |
| `note`, `nb_avis` | string, integer | recommended | rating as shown (`"9.1/10"`) and number of reviews |
| `points_forts`, `vigilance` | list of strings | recommended | strengths, things to watch |
| `acces` | string | optional | how to get there, one line |
| `annulation` | string | recommended | cancellation terms (`"free cancellation until 7 days before"`) |
| `photo_urls` | list of https strings | recommended | photo addresses, best first; the page downloads them |
| `photo_cover` | integer | optional | rank (1 = first) of the photo showing the view from the room |
| `top3` | boolean | optional | one of the favorites of the stage (shown first) |
| `folie` | boolean | optional | a splurge, above the usual budget |
| `pourquoi_pepite` | string | optional | one line: why this place is special |
| `prix_compares` | list of `{site, total_home, url, verifie}` | optional | the same stay priced on other sites |
| `url_meilleur_prix` | https string | optional | where the lowest price was seen |
| `sources` | list of strings | recommended | `"<url> (checked YYYY-MM-DD)"` |

A lodging without a deep fiche (below) shows in the page under "other lodgings", with an incomplete budget.

```json
[{"id": "lisbon-01", "etape": "lisbon", "nom": "Casa Miradouro Boutique Hotel", "plateforme": "Booking.com",
  "url": "https://www.example.com/sample/lisbon-01", "zone": "Alfama", "lat": 38.7128, "lng": -9.1306,
  "type": "boutique hotel", "vue": "Tagus river and terracotta roofs from the terrace", "prix_total_home": 600,
  "prix_nuit_home": 200, "nuits": 3, "note": "9.1/10", "nb_avis": 640, "top3": true,
  "annulation": "free cancellation until 7 days before",
  "photo_urls": ["https://upload.wikimedia.org/wikipedia/commons/b/b0/Alfama%2C_Lisbon_%28DSC03367%29.jpg"],
  "sources": ["https://www.example.com/sample/lisbon-01 (checked 2026-11-07)"]}]
```

### `logements-exclus.json` (stay-finder, shared: merge)

Lodgings removed after looking at their photos (dated, cheap-looking, not matching the travelers' taste):
`{"<lodging id>": "reason"}`. They disappear from the page; the reason stays for the record.

```json
{"lisbon-03": "dated rooms on the photos, view blocked by a building"}
```

### `resorts-fiches-<stage>.json` (stay-finder)

The deep fiche of a short-listed lodging (3 to 5 per stage): what is included, the real cost, the reviews. Any file
name starting with `resorts-fiches-` is read; one per stage avoids conflicts. Joined to the lodging by `id`. A
lodging with a fiche gets full budget lines in the page and becomes a default choice candidate.

| Field | Type | Meaning |
|---|---|---|
| `id`, `nom` | string | same id as in `logements-<stage>.json` |
| `pourquoi` | string | why it fits these travelers (first sentence shown on the card) |
| `chambre_conseillee` | string | the room type to book |
| `vue_depuis_chambre` | string | the view from that room |
| `public` | string | who the place suits |
| `prix` | object | `{total_home, nuit_home, plateforme, annulation, paiement, verifie, dispo, detail, url, autres}`: the verified price, which replaces the lodging's; `paiement` = when you pay (`"pay at the hotel"`, `"nothing before 2027-05-01"`); `dispo` = availability seen; `detail` = what the price includes; `autres` = `[{site, total_home, annulation, detail}]` other offers |
| `formules` | list of `{nom, detail, total_home}` | rate plans; a `detail` saying "book before <date>" becomes a deadline in the plan |
| `inclus`, `non_inclus` | lists of strings | included, not included |
| `equipements`, `restaurants` | lists of strings | facilities, restaurants on site |
| `gala` | string or null | a mandatory dinner (holiday gala...) and its price, as the hotel states it |
| `gala_pour` | string | key of the special evening (trip.json `specials`) that the gala dinner falls on |
| `avis` | object | `{sources, aiment, reprochent, citations, alerte}`: review sites, what guests like, what they dislike, short quotes, a warning or null |
| `acces` | string | access in one sentence |
| `cout_reel` | object | real cost of the stay by item, in home currency: `chambre` (room), `petits_dej` (breakfasts), `dejeuners` (lunches), `diners` (dinners), `gala`, `verres` (drinks), `spa`, `transferts` (airport transfers), plus `hypotheses` (how it was estimated) |
| `note_qualite`, `note_qualite_prix` | number 0 to 5 | quality, value for money |
| `verdict` | string | one line |
| `lat`, `lng`, `sources` | | as in the lodging |

```json
[{"id": "porto-01", "nom": "Casa da Ribeira Riverside Hotel", "pourquoi": "River views from every room.",
  "prix": {"total_home": 660, "nuit_home": 220, "plateforme": "Booking.com",
           "annulation": "free cancellation until 14 days before", "paiement": "pay at the hotel",
           "verifie": "2026-11-07", "url": "https://www.example.com/sample/price"},
  "gala": "Mandatory gala dinner on 23 June, 130 per person, drinks excluded", "gala_pour": "sao-joao",
  "cout_reel": {"chambre": 660, "petits_dej": 108, "dejeuners": 0, "diners": 185, "verres": 80, "transferts": 60,
                "spa": 0, "gala": 260, "hypotheses": "6 breakfasts at 18, 2 dinners, 5 drinks at 16, 2 taxis at 30"}}]
```

### `couts-unites.json` (stay-finder, shared: merge)

The on-site spending of each fiche, as units: `{"<lodging id>": {"<item>": [{n, u, lib, src}]}}`. Items are the
`cout_reel` keys (`petits_dej`, `dejeuners`, `diners`, `gala`, `verres`, `spa`, `transferts`). `n` × `u` = subtotal
(count × unit price), `lib` = label, `src` = `"carte"` (read on the menu or price list), `"estime"` (estimated, no
published price) or `"inclus"` (included). The lines of an item must add up to its `cout_reel` total (within 1.5),
otherwise they are ignored and the total shows as one estimated line.

```json
{"porto-01": {"gala": [{"n": 2, "u": 130, "lib": "gala dinner, per person", "src": "carte"}],
              "transferts": [{"n": 2, "u": 30, "lib": "taxi", "src": "estime"}]}}
```

### `acces-logements.json` (stay-finder, shared: merge)

How each fiche's lodging is reached from its airport; the page checks flight times against it (last boat, last
bus). Every lodging with a fiche needs an entry. `{"<lodging id>": {...}}`, all fields required:

| Field | Type | Meaning |
|---|---|---|
| `aeroport` | IATA code | one of the stage's `airports` or `depart_airports` in trip.json |
| `duree_min` | integer > 0 | door-to-door minutes from the airport |
| `mode` | words joined by `+` | how the lodging is reached, in order: `voiture` or `car`, `taxi`, `bateau`, `boat` or `ferry`, `train`, `bus`, `metro`, `tram`, `pied` or `walk` (`"voiture+bateau"`, `"train+walk"`). The page names each word ("by car then by boat"); the last public departure is called a boat when the mode has a boat or ferry, otherwise "transport" |
| `dernier_public` | `"HH:MM"` or null | last public departure (boat, bus) that still reaches the lodging |
| `premier_public` | `"HH:MM"` or null | first public departure |
| `prive_home` | number or null | price of a private transfer for the group |
| `source` | string | where the times and price come from |
| `verifie` | date | check date |

```json
{"comporta-01": {"aeroport": "LIS", "duree_min": 105, "mode": "voiture+bateau", "dernier_public": "20:30",
                 "premier_public": "07:00", "prive_home": 140, "source": "ferry operator timetable",
                 "verifie": "2026-11-07"}}
```

### `sources-photos.json` (stay-finder, optional, shared: merge)

Manual photo sources for a lodging whose listing gives none: `{"<lodging id>": {"agoda": [hotel ids], "trip":
[Trip.com hotel ids], "site": [page addresses]}}`. Read by `python3 scripts/photos.py tout`.

## Flights

### `vols-brut/` (flight-hunter, through the script)

Raw Kiwi answers, one file per flight leg, date and variant: `<leg>-<YYYYMMDD>[-<variant>][-valise].json` (`-valise`
= requested with a checked bag). Leg keys come from trip.json (`python3 scripts/tripctx.py` lists them:
`arrive-a`, `lisbon-comporta`, `return-b`...). Never write these by hand: `python3 scripts/flights.py --trip
trips/<slug> download` fetches them (free, slow: a few calls per minute), `python3 scripts/flights.py --trip
trips/<slug> build` turns them into `vols-options.json` (generated). `python3 scripts/build.py --download-flights` does
both.

### `vols-comparateurs.json` (flight-hunter, through the script)

Prices of the same flights read by hand on other sites (Google Flights, airline sites, Trip.com, Skyscanner...).
Write a hand-read file in the trip's research folder (`trips/<slug>/research/vols-releves-<YYYY-MM-DD>.json`, never
at the repository root) and merge it: `python3 scripts/flights.py --trip trips/<slug> comparateurs <that file>`, then
`build`. The hand-read file:

```json
{"verifie": "2026-11-07",
 "releves": [{"vol_id": "arrive-a-20270615-IB9002-IB9003", "site": "Airline website", "prix_home": 375,
              "pour": "1 adult", "detail": "basic fare, no checked bag", "url": "https://www.example.com/fare"}],
 "hausse": [{"vol_id": "arrive-a-20270615-IB9002-IB9003", "texte": "price expected to rise", "avant": "2027-01-15"}],
 "sites": {"Airline website": "direct booking, free changes"}}
```

`vol_id` is an option id from `vols-options.json`; a `vol_id` ending in `*` is the lowest price of that site for the
day (not the same flight). A site that shows a CAPTCHA is recorded with `"prix_home": null` and `"detail": "blocked
(CAPTCHA)"`: never bypassed.

## Ground legs and formalities

### `trajets.json` (logistics-planner, merge)

The ground legs between stages (legs whose mode is `ground` in `python3 scripts/tripctx.py`), and any other journey
worth showing on a day: `{"meta": {...}, "trajets": [...]}`.

| Field | Type | Meaning |
|---|---|---|
| `id` | string | the leg key (`lisbon-comporta`); the page shows its options as the leg's choices |
| `date` | date | the leg's date |
| `de`, `vers` | string | from, to (stage titles) |
| `conseil` | string | the advice in one or two sentences |
| `options` | list | `{mode, operateur, depart, arrivee, duree, prix_couple_home, lien, reserver, remarque}`: mode (`voiture`, `train`, `bus+bateau`...), operator, departure and arrival `HH:MM`, duration text, price for the group, booking link, when to book, a remark |

```json
{"meta": {"verifie": "2026-11-07"},
 "trajets": [{"id": "lisbon-comporta", "date": "2027-06-18", "de": "Lisbon", "vers": "Comporta",
   "conseil": "By car it is simple; the last public ferry leaves at 20:30.",
   "options": [{"mode": "voiture", "operateur": "Rental car", "depart": "10:00", "arrivee": "11:45", "duree": "1 h 45",
                "prix_couple_home": 96, "lien": "https://www.example.com/sample/car-rental", "reserver": "a week ahead",
                "remarque": "fuel included in the price"}]}]}
```

### `formalites.json` (logistics-planner, shared: merge)

Everything to do before leaving, per traveler: entry rules, arrival card, insurance, eSIM, vaccines... A list; every
field is required.

| Field | Type | Meaning |
|---|---|---|
| `code` | string, unique | short id (`insurance`, `entry-a`) |
| `qui` | string | a traveler id of trip.json, or `"all"` |
| `titre` | string | what to do |
| `cout_home` | number >= 0 | cost per person concerned (0 = free); counted in the budget |
| `delai_jours` | integer >= 0 | days it takes |
| `avant` | `"depart"`, `"arrivee"`, `"fin-30-jours"` or null | deadline: before departure, before arrival, before the end of a 30-day stay |
| `condition` | string or null | `code` of another formality this one depends on |
| `url_officielle` | https string | the official site (never a paid look-alike) |
| `source`, `verifie` | string, date | where the rule was read, check date |

`trip.json` `required_formalities` lists the codes that must exist.

```json
[{"code": "entry-a", "qui": "a", "titre": "Entry authorisation for a US passport", "cout_home": 12, "delai_jours": 3,
  "avant": "depart", "condition": null, "url_officielle": "https://www.example.com/sample/entry-a",
  "source": "official immigration site", "verifie": "2026-11-07"}]
```

### `taux.json` (budget-keeper)

The exchange rate shown in the page: `{"taux": <local units for 1 home unit>, "date": "YYYY-MM-DD", "source":
"..."}`. Only read when trip.json has a `currency.local`.

```json
{"taux": 0.92, "date": "2026-11-07", "source": "ECB rate via the currency server"}
```

## Places and outings

### `lieux-<stage>-activites.json` (activity-scout), `lieux-<stage>-restos.json` (food-scout)

The places of a stage: `{"pois": [...]}`. (`carte-<stage>.json`, same shape, is also read: extra places for the map.)

| Field | Type | Meaning |
|---|---|---|
| `id` | string | `<stage>-<short-name>`, unique in the trip |
| `nom` | string | name |
| `categorie` | string | one of: `sight`, `viewpoint`, `beach`, `nature`, `activity`, `market`, `adventure`, `restaurant`, `street food`, `cafe`, `bar`, `rooftop`, `evening`, `wellness`, `event`, `info` (`info` = information only, no outing). Older French values are also read. |
| `sous_type` | string | finer type (`walking tour`, `set menu dinner`) |
| `zone`, `lat`, `lng`, `approx` | | area, position, `approx: true` when the position is approximate |
| `resume` | string | one line: what it is |
| `pourquoi` | string | why it fits these travelers |
| `incontournable` | boolean | a must |
| `score` | number 0 to 5 | fit with the brief |
| `tags`, `distinctions` | lists of strings | themes; awards and guides |
| `notes` | list of `{site, note, avis, url}` | ratings: site, score, number of reviews, link |
| `prix` | string | price as text (`"about 70 for the group"`) |
| `prix_couple_home` | number | price for the group |
| `duree`, `horaires`, `meilleur_moment` | string | duration, opening hours, best time |
| `plats` | list of strings | dishes to order (restaurants) |
| `a_reserver`, `reserver_quand`, `lien_reservation` | boolean, string, https | booking needed, when, where |
| `lien` | https string | official page |
| `fetes`, `dates` | string, list of dates | festivals, dated events |
| `acces` | string | how to get there from the lodging |
| `photo_urls` | list of https strings | up to 6 photos |
| `sources` | list of strings | sources with check dates |
| `meme_lieu_que` | string | id of another outing at the same place (another time of day) |

```json
{"pois": [{"id": "lisbon-alfama-walk", "nom": "Alfama morning walk with a local guide", "categorie": "activity",
  "sous_type": "walking tour", "zone": "Alfama", "lat": 38.7115, "lng": -9.13, "approx": true,
  "resume": "Two hours through lanes and viewpoints before the crowds.", "pourquoi": "Gentle pace, ends with a coffee.",
  "score": 4.3, "prix": "about 70 for the group", "prix_couple_home": 70, "duree": "2 h 30", "a_reserver": true,
  "reserver_quand": "the day before", "lien": "https://www.example.com/sample/place/lisbon-alfama-walk",
  "photo_urls": [], "sources": ["https://www.example.com/sample/place/lisbon-alfama-walk"]}]}
```

### `lieux-agenda.json` (events-hunter, shared: merge)

Dated events of the whole trip: `{"pois": [...]}`, same fields as the places plus `etape` (the stage key), `dates`
and `horaires`. Two kinds of entries:

- an **event** the travelers can choose (`categorie` `event` or another place category): it needs `lat`/`lng` and its
  outing in `sorties-<etape>.json` (the checks report an event without one);
- an **info** entry is `categorie: "info"` (it may omit coordinates): a closure, a public holiday, a strike. It needs
  no outing; without coordinates it shows as a note on its days.

```json
{"pois": [
  {"id": "porto-sao-joao-party", "etape": "porto", "nom": "Street party and fireworks", "categorie": "event",
   "lat": 41.1408, "lng": -8.6118, "approx": true, "dates": ["2027-06-23"],
   "horaires": "from 21:00, fireworks at 00:00",
   "resume": "The whole riverside celebrates.", "prix_couple_home": 0,
   "lien": "https://www.example.com/sample/festival",
   "sources": ["https://www.example.com/sample/festival (checked 2026-11-07)"]},
  {"id": "porto-holiday-24", "etape": "porto", "nom": "Public holiday", "categorie": "info", "dates": ["2027-06-24"],
   "resume": "Museums and many shops closed in the morning.", "sources": ["https://www.example.com/sample/holidays"]}
]}
```

### `sorties-<stage>.json` (activity-scout, food-scout, events-hunter; shared: merge)

What the page offers to choose for the stage: one outing per place (every place of the stage except `info` needs
one, and every outing needs its place in a `lieux-*.json` file). `{"<place id>": {...}}`:

| Field | Type | Meaning |
|---|---|---|
| `prix_couple_home` | number or null | price for the group; null = unknown |
| `compris`, `pas_compris` | lists of strings | included, not included |
| `duree_min` | integer > 0 | duration in minutes |
| `depart` | `"HH:MM"` or null | start time |
| `moment` | string | `aube` (dawn), `matin` (morning), `journee` (all day), `apres-midi` (afternoon), `coucher` (sunset), `soir` (evening) |
| `date_fixe` | date or null | only on that date (inside the trip) |
| `jour_trajet_ok` | boolean | fits on a travel day |
| `quand_reserver` | string | `maintenant` (now), `vite` (soon), `veille` (the day before), `sans` (no booking) |
| `remplace` | string or null | the lodging budget item it replaces: `diners`, `dejeuners`, `spa`, `verres` (a dinner out replaces a dinner at the hotel) |
| `liens` | list of `{site, prix_home, url, verifie}` | where to book, the price read there and when |
| `reveillon` | boolean | old field, keep `false` (use `speciale`) |
| `hausse` | null or `{avant, prix_apres_home}` | the price rises after that date, to that amount |
| `speciale` | string or null (optional) | key of the special evening of trip.json it belongs to |
| `prix_estime` | boolean (optional) | `true` when no link quotes the price (an estimate) |

No price without a source: a price needs a link whose `prix_home` quotes it (0 for a free place), or
`prix_estime: true`.

```json
{"lisbon-alfama-walk": {"prix_couple_home": 70, "compris": ["guide", "coffee"], "pas_compris": [], "duree_min": 150,
  "depart": "09:00", "moment": "matin", "date_fixe": null, "jour_trajet_ok": false, "quand_reserver": "veille",
  "remplace": null, "liens": [{"site": "Walking tours", "prix_home": 70,
  "url": "https://www.example.com/sample/book/lisbon-alfama-walk", "verifie": "2026-11-07"}],
  "reveillon": false, "hausse": null}}
```

### `photo-guides.json` (optional)

A list of host name fragments of local guide sites (`["localguide.example"]`): `python3 scripts/place_photos_extra.py`

## Generated and other files

| File | What it is |
|---|---|
| `vols-options.json` | flight options built from `vols-brut/` (`scripts/flights.py build`) |
| `lieux-photos-extra.json`, `poi-cache/` | extra place photos found by `scripts/place_photos_extra.py` |
| `medias-cache/` | photo download cache of `scripts/photos.py` |
| `previews/` | photo strips made by `scripts/photo_strip.py` to show options in the chat, and the option lists they are made from (`options-<topic>.json`) |
| `vols-releves-<date>.json` | hand-read flight prices, merged into `vols-comparateurs.json` by `scripts/flights.py comparateurs` |
| `photo-credits.json` | the sample's credits for its free-licence photos (not read by the scripts) |
| `apify-ledger.md` | one line per paid Apify run: actor, goal, volume, cap, real cost, credit left |
| `videos.json` | optional videos by place id (not produced in this version) |
